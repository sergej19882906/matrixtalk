- **Старые Windows-записи снова играют** — голосовые, записанные desktop-клиентами до версии 1.43, лежали на сервере как сырой PCM без WAV-заголовка (баг №11 аудита); встроенный плеер их отбрасывал во внешний. - Декодер Opus принимает `channelMappingFamily 1` (1–2 канала) — некоторые продюсеры используют его даже для моно
- Починен регресс: линия звука, не открывшаяся при старте, теперь закрывается до переключения на внешний плеер

## 1.44.0
**Дата:** 2026-11-05 — пять функций паритета с Element: multi-select сообщений, стикер-паки (MSC2545), жалобы на сообщения, деактивация аккаунта и live-геолокация (MSC3488).

### 💬 Чат
- **Multi-select сообщений** — пункт «Выбрать» в меню сообщения: выбор нескольких сообщений, пакетное удаление и **пересылка в другую комнату** (текст уходит как текст, медиа перекачивается с сохранением исходного MIME и при необходимости перешифровывается под целевую комнату, опросы пересоздаются как новый опрос)
- **Стикер-паки (MSC2545)** — полноценный пикер вместо выбора файла: паки из глобальных `im.ponies.user_emotes`, комнат из `im.ponies.emote_rooms`/`packs` и текущей комнаты (`im.ponies.room_emotes`); совместим с Element/Cinny (читает и старый ключ `emotes`, и новый `images`); **добавление паков по ссылке** (matrix.to / `#алиас:сервер` / `!roomId:сервер`) с автоприсоединением к комнате, управление подписками прямо в пикере
- Типизированный `m.sticker` вместо Unknown-JSON: входящие стикеры в зашифрованных комнатах теперь открываются (раньше отбрасывались), отправка через fail-closed sender
- **Жалобы на сообщения** — «Пожаловаться» в меню чужого сообщения, опциональная причина, отправка на стандартный report-эндпоинт
- **Live-геолокация (MSC3488)** — «Live-геолокация» в меню вложений: трансляция 15 мин / 1 час / 8 часов, беacons каждые 10 секунд, карточка с таймером и кнопкой «Остановить»; на десктопе просмотр чужих биконов работает, трансляция недоступна (нет GPS)

### ⚙️ Аккаунт и безопасность
- **Деактивация аккаунта** — в настройках с двойным подтверждением и вводом пароля (UIA), опция «стереть мои сообщения»; после деактивации локальная сессия полностью сбрасывается

### ⚠️ Ограничения
- Live-геолокация транслируется из **foreground-сервиса** (type=location, постоянное уведомление с кнопкой «Остановить») — биконы идут, пока активна трансляция, даже если приложение свернуто; если Android принудительно остановил процесс (force stop / агрессивная батарейная оптимизация), трансляция прерывается до следующего запуска. Биконы старше timeout скрываются по правилам MSC3488
- Пересланный опрос создаётся заново в целевой комнате без голосов; настройки «скрытый результат» и «макс. выборок» берутся по умолчанию

## 1.43.0
**Дата:** 2026-11-05 — выпуск по итогам аудита (`docs/AUDIT-2026-11-05.md`, 24 дефекта): безопасная отправка E2EE-контента, исправленный envelope голосовых, рабочий выход/PIN, корректная регистрация UnifiedPush, правки чата, плееров и серверного стека.

### 🔐 Матрица-протокол и E2EE
- **Fail-closed sender для зашифрованных комнат** — файлы, стикеры, опросы, геолокация и custom-события больше не уходят на сервер с открытым ключом `EncryptedFile`: событие сначала шифруется через `RoomEventEncryptionService`, и только `m.room.encrypted` отправляется наружу; ошибка шифрования не переключает отправку на plaintext (было: ключи вложений попадали homeserver)
- Устранён контент с одновременными `url` и `file` (выражение `fileInfo?.let { null } ?: mxc` всегда выбирало mxc)
- **Голосовые сообщения** отправляются стандартным `m.room.message` с `msgtype=m.audio`, duration/waveform (MSC3245/MSC1767) через специализированный сериализатор; входящие voice-маркеры читаются, обычные аудио не затрагиваются
- **Медиа-resolver** не зависит от памяти: после перезапуска файлы резолвятся из персистентного хранилища, включая E2EE; корректное расширение по MIME
- **Завершение опросов работает** — агрегация ответов/завершений локальна для комнаты, учитывает автора и временную границу голосов (недостижимая ветка удалена)
- **Бейдж моста** читается из room state `m.bridge` (MSC2346) и legacy `uk.half-shot.bridge` с приоритетом displayName
- Сигналинг чужих звонков (answer/candidates/hangup) игнорируется: проверка room/call/peer в репозитории и в обоих WebRTC-движках
- Входящие/исходящие голосовые vs видеозвонки различаются во всех ветках маппинга, включая типизированные `m.call.invite` от Element

### 🔑 Сессия, PIN и выход
- **Кнопка «Выйти» реально завершает сессию**: repository logout под мьютексом lifecycle, остановка sync/call/audio/background jobs, очистка кэшей и push-регистрации; ошибки сервера показываются и отличают локальный выход от отзыва токена
- **PIN-блокировка подключена**: диалог настройки, salted PBKDF2, обязательный текущий PIN для смены/отключения, задержка после неудачных попыток, повторная блокировка при уходе в фон; состояние реактивное, без runBlocking
- **SessionStore**: атомарная запись файла, cache только после успешной записи, единый mutex на read-modify-write, ошибки не подавляются

### 🔔 Push и уведомления
- **Регистрация UnifiedPush исправлена**: `SetPushers` именованными аргументами (`kind=http`, правильные appId/pushkey), receiver `exported=true` по контракту дистрибьютора, проверка источника broadcast
- Фоновый воркер соблюдает in-app настройки (тумблер, mute, «только упоминания»), ждёт пригодную расшифровку, дедуплицирует после обработки; при выключении/выходе отменяются работы и удаляется pusher
- Режим «Упоминания» переключает весь релевантный набор стандартных правил (`.m.rule.message`, DM/encrypted-правила), ошибки API видны
- **Кириллические ключевые слова** получают collision-resistant ID (SHA-256) — «работа» и «привет» больше не перезаписывают друг друга

### 💬 Чат и экраны
- Реакции, receipts, thread-chip и summary больше **не накладываются** на пузырь сообщения — вертикальная структура; поиск зарезервирован отдельной строкой
- SYSTEM-события — отдельная неинтерактивная строка; описания membership сравнивают prev_content (смена имени/аватара не «новое вступление»)
- Ветки (Threads): подключены реальные действия, корень и страницы ответов загружаются независимо; неподдержанные действия скрыты
- Spaces: пагинация иерархии, достоверная типизация room/space, preview/join для невступивших детей
- Element Call WebView: origin/resource allowlist для разрешений, корректный partial-grant flow, освобождение WebView и отмена pending-запросов
- Запись видео проверяет runtime CAMERA-разрешение и обрабатывает отказ/отсутствие capture activity

### 🎙 Голос и медиа
- **Desktop-запись** пишет валидный RIFF/WAVE с финализацией размера; поток завершён до возврата файла
- Встроенный плеер распознаёт голосовые без расширения (sniff контейнера по байтам: WAV, Ogg/Opus), fallback на внешний плеер сохранён
- Плееры Android/Desktop: владение сессией воспроизведения (generation), отмена устаревших prepare/потоков, корректный drain и позиция — гонки при переключении треков устранены

### 🐳 Серверный стек
- Все 8 мостов подключены к auto-конфигурации Synapse: registration mounts + scanner, ручные appservices не затираются; entrypoint-скрипты сверены с upstream
- ntfy: ключ `cache-file`, отдельный entrypoint; конфигурационные тесты (`docker/tests/test_configuration.py`) проверяют compose- и entrypoint-инварианты

### 🧪 Тесты
- Новые регрессионные наборы: wire-serialization (voice envelope, bridge state, call contents), SecureRoomEventSender (отсутствие ключа в незашифрованном событии), SessionStore (write failure/concurrency), AppLockManager (throttle/lifecycle), PushProtocol (payload/shouldNotify), плееры (session cancellation), AudioDecode (WAV/Ogg), docker-конфигурация

### ⚠️ Ограничения
- Реальные звонки между двумя клиентами, доставка UnifiedPush на живом устройстве и notarized-подпись в этой версии автоматическими проверками не покрыты — тесты валидируют протокольный слой и логику
- Известные нереализованные функции Element — см. `docs/AUDIT-2026-11-05.md` и README
